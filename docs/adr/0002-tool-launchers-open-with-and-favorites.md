# Separate global Sidebar Tool Launchers from contextual Open-with file handoff

Repeating favorite tool buttons across the Left Sidebar, the `My PDFs` top-right action bar, the `View PDF` header, and both `Favorites` and `Popular Tools` sections in `All tools` created visual duplication and ambiguous file-handoff behavior. We separate **Tool Launchers** into two distinct roles backed by a single user-customizable **Favorites** list (seeded with `Compress PDF`, `Merge PDF`, `Convert`, and `Sign PDF`): global navigation in the Left Sidebar `Tools` rail (capped to the user's top 6 Favorites, always opening a fresh empty **Tool Surface**) and a unified contextual `Open with` dropdown menu in both `My PDFs` and `View PDF` (listing all Favorites, then deduped Popular Tools, then `Browse all tools…`, with non-PDF-input entries, single-file entries when $>1$ PDF is selected, and `Compare PDFs` when $>2$ PDFs are selected kept visible in order but disabled with an explanatory tooltip). Only `Open with` — including its `Browse all tools…` hop into `All tools` — arms file seeding for the selected or open PDF(s) (including seeding 1 or 2 selected PDFs into `Compare PDFs`), and in `All tools` the `Favorites` section replaces the separate `Popular Tools` grid category while keeping favorited **Catalog Entries** visible in their home domain categories.
