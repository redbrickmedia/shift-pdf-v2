# Unify Tool Surface commit actions in the header toolbar and make output publishing pure staging

Boxed tools previously rendered both an in-card `#process-btn` and the top-right `viewer-chrome` header toolbar (`Save`, `Overwrite`, `Download`, `Print`), custom-layout tools (`pdf-multi-tool`, `bookmark`, `markdown-to-pdf`, `form-creator`) bypassed `viewer-chrome`, and `downloadFile()` (`PDF_OUTPUT_READY_EVENT`) simultaneously staged output for the header, auto-saved PDFs to `My PDFs`, prompted to overwrite `FileSystemFileHandle` entries on disk, and opened the `#shift-tool-success` modal. We mount the shared `viewer-chrome` header across every **Tool Surface** (showing `Undo`/`Redo` only on the 6 stateful interactive surfaces and hiding `Save`, `Overwrite`, and `Print` whenever the active surface or mode outputs a non-PDF artifact or is on the read-only `Validate Signatures` tab) and make it the single primary commit surface (hiding in-card `#process-btn` and primary export buttons universally, keeping only secondary granular exports like `.txt`/`.csv`/per-item downloads inline, and re-running `applyToolOutput()` fresh on every commit). `downloadFile()` becomes pure output staging (retiring `#shift-tool-success` and the global disk-handle interceptor so `Save` adds new `My PDFs` entries including unpacked `.pdf` files from multi-PDF `.zip` results, `Overwrite` updates the targeted `My PDFs` entry and its `FileSystemFileHandle` in place, `Download` only triggers a browser download, and both `Save` and `Overwrite` keep the user on the active Tool Surface with a confirmation alert).
